# Foodiemo v2 測試流程

更新日期：2026-09-09

文件狀態：測試規劃；第一批執行結果見 [本批紀錄](docs/test-report-2026-09-09.md)，未列通過者不可視為完成。對應 [v2開發流程](v2開發流程.md)。

## 1. 驗收目的與優先順序

v2 首要驗收是：**原始前端的畫面、手勢、頁面路徑與操作仍然成立，背後資料已改接 PostgreSQL，推薦提供者可替換。**

驗收順序：

1. 是否保留已定案的使用流程。
2. 資料是否真的讀寫到新 DB，重新整理與跨頁是否一致。
3. 身分、所有權、照片與會員是否由後端正確控制。
4. 推薦契約、偏好與互動事件是否可供演算法接入。

新增搜尋欄、改用分頁替代下拉、更換首頁或刪除原入口，即使 API 全通過仍判定不符合需求。

## 2. 測試環境隔離

| 環境 | 用途與限制 |
| --- | --- |
| project_db | 唯讀盤點與必要真實餐廳瀏覽；結構變更前另做備份；禁止自動清表、造測試資料與故障注入 |
| foodiemo_v2_test | 專用 PostgreSQL 整合／API／瀏覽器 fixture；專用角色，與正式及 v1 測試庫分離 |
| 新建備份還原 DB | 只做還原驗證，禁止拿備份中的真實使用者資料當功能測試 fixture |
| v2開發/test-uploads/ | 獨立測試照片；建立／刪除前核對解析後絕對路徑 |
| 隔離瀏覽器 context／來源 | 不沿用正式帳號、localStorage、IndexedDB 或 Service Worker |
| 原版基線環境 | 操作與畫面對照；必要測試替身明示標記，不能當成外部串接證據 |

自動化功能測試進行任何寫入、migration、種子資料或清理前，測試入口都必須確認：

- APP_ENV 明確為 test。
- DB 名稱精確為 foodiemo_v2_test，而非模糊含有 test 即放行。
- 主機／埠與預先指定的測試目標一致。
- 明確測試寫入標記。
- 連線後再次核對 current_database()、使用角色與資料庫端隔離標記。
- 照片實際路徑位於已確認的 v2 專用測試目錄。

任一條件不符立即停止。不得失敗後改到 project_db 執行。PostgreSQL 型別、JSONB、外鍵、交易與 migration 不用 SQLite 替代。

備份還原驗證使用獨立入口，精確核對本次新建還原庫的名稱、角色及目標；不能放寬功能測試入口的白名單。正式 migration 依開發流程的備份與變更程序處理，不由功能測試入口執行。

## 3. 原版對照與測試證據

### 3.1 建立基線

逐頁記錄原版 URL、入口、按鈕、操作、預期返回位置、圖像與文字區塊、手勢及資料來源。至少覆蓋：

- index、home、search、memories、edit、social、comments。
- login、signup、otp_verify、onboarding、forgot-password、reset_password。
- profile、payment、message。

建立原版與 v2 同一裝置尺寸、同一人工資料、同一操作步驟的對照。截圖不能只比顏色；需檢查元素位置、照片比例、按鈕與操作步驟。動態照片、時間與已確認的來源／錯誤文案可列為允許差異，不採未經檢視的整頁 snapshot 自動更新。

原版既有 bug 單獨記錄「原始實際行為」與「應保留的操作意圖」，例如取消捨棄應留頁，而不是要求 v2 重現 bug。

### 3.2 測試層次

- 邏輯測試：映射、日期、順序、提供者輸出驗證及安全入口。
- PostgreSQL 整合：migration、型別、約束、交易、所有權與重送。
- API 契約：原前端期望的欄位、回應與錯誤，不能只驗新設計 API。
- 瀏覽器：點擊、輸入、重新整理、返回、下拉與多圖流程。
- 手機實機：主容器側滑、相簿橫滑、限動點擊／下拉、相機與軟鍵盤。

瀏覽器 route mock、測試提供者與寄信替身各自標記；不可用替身通過聲稱真實 DB、真實郵件或演算法服務成功。

## 4. 每次執行順序

1. 記錄日期、Git commit／程式快照、DB 版本與 migration、測試範圍。
2. 確認環境隔離、Tunnel、API、測試帳號及儲存目錄。
3. 選定本階段互動基線與允許差異。
4. 建立固定最小 fixture，避免依賴正式筆數。
5. 執行本次受影響的邏輯、PostgreSQL、API 測試。
6. 執行原版操作路線及錯誤分支，檢查手機尺寸與必要實機手勢。
7. 失敗定位後修正，再重跑失敗及相鄰流程。
8. 清理此次 fixture／照片，核對沒有刪到其他資料。
9. 保存去除機密的結果，列明未測與待確認事項。

安裝與啟動命令待實際工具建立後補入 v2 README；目前不借用 v1 命令宣稱 v2 已可執行。

## 5. 最小測試資料

- A、B 兩個不同帳號；未登入、登入過期、普通會員、有效／到期會員。
- 餐廳完整資料、缺值、特殊字元、非連續與超過 JavaScript 安全整數範圍的 ID。
- 餐廳候選數為 0、1、2、3、超過 3；固定候選與種子，測試可重現。
- 六題不同偏好、非法選項、缺題、舊版本，以及 A/B 各自的偏好。
- 單圖／多圖、同日不同紀錄、跨日／跨月、只剩最後一圖與最後一篇。
- 新舊照片混合、不同壓縮耗時、重複上傳、偽裝圖片、過大檔案。
- 留言一般文字、空白、換行、HTML 特殊字元、軟刪除及非法目標。
- 推薦提供者正常、空結果、失敗、逾時、重複／無效 ID、重複排名。
- 會員與模擬交易使用受控時間、固定重送識別。

正式 DB 中的餐廳／評論總數不作固定斷言；照片與使用者資料不得直接取自正式庫當 fixture。

## 6. 分階段案例

### A. 環境、資料保護與版本

| 編號 | 情境 | 預期 |
| --- | --- | --- |
| ENV-01 | 唯讀核對正式 DB | 版本、Schema、權限、Alembic 狀態可核對；無隱藏寫入與敏感列輸出 |
| ENV-02 | 缺設定、錯誤帳密、不可達目標 | 明確失敗；不切 SQLite 或假資料 |
| ENV-03 | 隔離環境 Tunnel 中斷、恢復 | API 有界逾時；原頁顯示失敗；恢復後可重試 |
| ENV-04 | 本次完整備份與新 DB 還原 | Schema、逐表筆數、關聯及必要物件核對；備份被 Git 排除 |
| ENV-05 | 接續既有 migration | 不重跑已標記基線、不覆蓋既有版本、不重建正式表 |
| ENV-06 | 空測試庫重建、再次 upgrade | 完整結構可建立；不重複套用 |
| ENV-07 | 回復策略 | 在隔離庫驗證 downgrade 或新 DB 備份還原；資料損失限制明列 |
| ENV-08 | 誤設正式／v1／還原庫、錯主機／埠／標記 | 寫入及清理前拒絕 |
| ENV-09 | 測試照片路徑指向正式或越界 | 拒絕上傳、清理與刪除 |
| ENV-10 | Git 待提交檔案 | 原始設定、帳密、Token、備份、上傳與含個資證據未納入 |

### B. 原版畫面與主容器

| 編號 | 情境 | 預期 |
| --- | --- | --- |
| UI-01 | 登入後開主容器 | 左日曆、中首頁、右社群，預設首頁；不是餐廳列表首頁 |
| UI-02 | 左右滑、短滑、邊界外拉 | 原方向、約五分之一門檻、回彈與阻力保留 |
| UI-03 | 指定 tab／子頁返回 | 回原來源，不無故回首頁或重置錯分頁 |
| UI-04 | 視窗旋轉／尺寸變化 | 三頁對齊，不露出半頁或錯位 |
| UI-05 | 限動開啟與關閉 | 開啟鎖外層側滑，關閉恢復 |
| UI-06 | 頁面上下捲、貼文照片橫滑 | 不誤切主容器；需手機實機確認 |
| UI-07 | 原版與 v2 畫面對照 | 主要佈局、按鈕、照片比例、選項一致；差異均在清單內 |
| UI-08 | 原版未有的操作 | 不出現新增搜尋、分類、分頁、收藏、評分或公私控制 |
| UI-09 | 示意／無事件入口 | 未擅自移除或擴充；串接狀態如實記錄 |

### C. 原式三間餐廳推薦

| 編號 | 情境 | 預期 |
| --- | --- | --- |
| REST-01 | 首頁放大鏡→推薦 | 自動請求 count=3，顯示原式直向大圖卡 |
| REST-02 | 頂端下拉超門檻／未超門檻 | 超門檻新請求替換整批；未超門檻回彈；不是分頁或追加 |
| REST-03 | 列表非頂端滑動 | 正常捲動，不誤觸刷新 |
| REST-04 | 手機與滑鼠下拉 | 原本兩種操作都能完成；連續動作不重複堆疊卡片 |
| REST-05 | 點卡→詳情→關閉 | 原覆蓋式詳情、欄位、動畫與列表位置保留 |
| REST-06 | 地圖與返回 | 開正確餐廳地圖；無連結有明確狀態；返回首頁 |
| REST-07 | 非連續／大 ID、特殊字元 | 身分不錯置、不丟 bigint 精度、不執行 HTML |
| REST-08 | 缺照片、評分、價位、時間、地址 | 原位置合理缺值，不造資料、不標成 Google 真實來源 |
| REST-09 | 候選 0／1／2／3／多筆 | 空與不足正確；不湊重複餐廳；候選充足依契約輪替 |
| REST-10 | 慢請求、重複下拉、舊回應晚到 | 保持最新操作結果，不被舊批次覆蓋 |
| REST-11 | API 失敗、空結果與重試 | 失敗不同於空；不無聲切內建店家；可在原操作下恢復 |
| REST-12 | 契約映射 | 原欄位可用；source 正確；詳情不擅自改成評論清單 |

| PREF-04 | 保存失敗與重試 | 保留選擇並可恢復，不假完成 |

| REC-18 | 地點與 Tagged | 不當成真實使用者／餐廳關聯；不自行增加選人選店器 |

## 7. 完整操作路線

依階段可用性逐步加入，未實作路線不得填通過：

1. 普通註冊 → 四位 OTP → 六題偏好 → 首頁 → 登出再登入 → 後端偏好仍在。
2. 首頁 → 放大鏡 → 3 間推薦 → 下拉換一批 → 點卡詳情 → 地圖 → 關閉 → 首頁。
3. 快門 → 相簿多圖 → 直接上傳 → 首頁更新 → 日曆限動 → 我的社群。
4. 鉛筆 → 單選／多選 → Finish → 社群編輯 → 保留舊圖加新圖 → 重整核對順序。
5. 月曆 → 限動左右點與自動播放 → 下拉關閉 → 單圖刪除 → 社群整篇刪除 → 三頁沒有殘留。
6. 我的社群 → 留言 → Post／Enter → 重整 → 返回社群。
7. 個人頁換頭像／失焦改名 → 首頁／社群／留言顯示一致 → 切換帳號不混用。
8. 已確認的模擬會員 → 成功／取消 → 回正確來源 → 後端資格一致。
9. 替換推薦提供者 → 重跑第 2 條 → 核對偏好、runs、items 與事件。
10. API 中斷、逾時、空資料、登入過期、提交失敗 → 在原流程下可辨識並恢復。

至少一台手機實機驗證相機、軟鍵盤、主頁側滑、相簿橫滑及限動下拉；只有模擬裝置時明確寫「實機未驗證」。PWA 更新後檢查頁面／腳本一致、登出後私人快取不殘留。

## 8. 通過與阻擋標準

以下任一情況阻擋該階段完成：

- 未確認就改掉原版頁面、入口、手勢或流程。
- 正式資料被測試寫入／清理，或測試檔案操作越界。
- 資料遺失、照片順序錯置、跨帳號存取、私人照片洩漏、腳本注入。
- UI 宣告成功但資料未保存、用舊快取掩蓋登入失效或 API 失敗。
- 推薦關聯錯帳號、模擬交易／會員狀態不一致。

畫面與資料／權限都通過才標記階段完成。待確認、外部供應商未設定、手機未驗或未實作皆分別記錄，不以推測或其他測試替代。不因一輪成功就無目的重跑全部；修正後重跑受影響流程，里程碑再做核心回歸。
