# 手機選圖、滑動及反應速度改善

## 已確認問題與修正

- 新建 edit 頁面沒有執行 renderGrid，造成加照片入口完全沒建立。改在初始化建立縮圖區，空白預覽提供「選擇手機照片」按鈕，呼叫 multiple 檔案選擇器。手機網頁需先由使用者選取授權，不能自動列出整個系統相簿。
- 編輯頁移除同步等待遠端 Lucide 腳本，改用內嵌 SVG，斷網或 CDN 慢時仍有圖示及選圖入口。
- 首頁手勢加入 12 px 容差與水平／垂直方向鎖定；水平位移需大於垂直 1.4 倍才啟動側滑，保留原五分之一寬度的翻頁門檻。上下滑或輕微晃動不更新主頁位置、不啟用遮罩。touchcancel 復位；Safari 工具列僅改高度時不重排三頁。
- 大照片在選取後沿用既有縮圖方法，先處理再建立預覽；同一張照片重用 Blob URL，避免反覆點縮圖時累積新的預覽 URL。最多十張。既有紀錄編輯時還原大預覽。
- 主頁子 iframe 重用同一身分請求；同時、相同條件的 get_memories 合併為一次 HTTP，每個讀取者取得獨立 Response。回應結束立即移除，不持久快取，後續請求重新讀取資料。
- GET／HEAD 不再另外執行檔案垃圾清理交易；保存／刪除等操作提交後仍清理，失敗上傳回滾策略不變。

## 驗證

49 項單元與 14 項隔離 PostgreSQL 通過；11 項真實隔離 API 瀏覽器流程通過（不寄真實測試信）；36 項原主頁／推薦回歸通過。

navigation-touch.cjs 在 390／412 px 驗證縱向滑動不改首頁位移、鉛筆導頁、原生多選檔案選擇器、縮圖顯示、Blob URL 重用及 Back；並驗證同時兩個紀錄請求只產生一次 HTTP，後續請求仍重新讀取。原 CSS 與原始前端檔案完整性檢查通過。

尚待使用者以 iPhone Safari 實測手感；上述為已移除的額外工作與模擬驗證，不宣稱完整端到端耗時已有特定百分比改善。VPN／遠端資料庫延遲仍可能影響操作。
