## 目前前後端綁定

- 帳號：`users`、`email_challenges`、`auth_tokens`、`login_limits`、`user_preferences` 對應註冊、Email OTP、登入、忘記密碼與六題偏好。
- 美食紀錄：`records` 與 `photos` 對應首頁快門、右下角畫筆、多圖順序、刪除與重新編輯。
- 留言與愛心：`platform_comments`、`record_likes` 對應貼文留言數、留言內容與愛心數。
- 標註：`record_mentions` 對應快門／畫筆的好友標註；地點 ID 寫入 `records.restaurant_id`，照片 EXIF GPS 的顯示標籤寫入 `records.location_text`。
- 好友與聊天：`friend_requests`、`chat_messages` 對應好友搜尋、邀請、批准、好友列表與私有聊天室。
- 會員：`memberships`、`payment_transactions` 目前是 Demo 付款，不會連接真實金流。
- 推薦：餐廳原始資料已存在；`recommendation_runs`、`recommendation_items` 與互動事件目前為空，推薦演算法尚未接入正式流程。

## 權限與資料安全現況

- 目前盤點連線回報 `transaction_read_only=on`，本次未執行寫入。
- API 以登入 Session 判斷使用者；照片檔案由作者限定讀取，好友關係不會自動開放私人照片。
- 圖片上傳會重新實體化為 JPEG，原始 EXIF 不會直接保存；照片 GPS 只保存為前端顯示用的短地點文字。
- 本文件與 Git 提交不放入 `.env`、SMTP 密碼、資料庫密碼、Session Token 或照片檔案。

## 持續更新流程

1. 修改 migration 或資料庫綁定前，先建立新的本機備份並記錄目錄。
2. 套用後執行 `scripts/inspect_db.py` 或同等唯讀盤點，更新本文件的版本、表格與筆數。
3. 在「更新紀錄」新增日期、migration／API 變更、備份位置與測試結果。
4. 執行來源保護、單元、瀏覽器與需要的 PostgreSQL 整合測試。
5. 將本文件與程式變更一起提交並推送到 GitHub。
