## 目前前後端綁定

- 帳號：一般使用者仍需 Email OTP 驗證；`users.username` 是公開、可修改且唯一的搜尋／登入帳號。唯一首位管理員使用 `email=NULL` 與 `email_auth_exempt=true` 登入，這個旗標受 DB 約束，只能存在於無 Email 的 admin 帳號且最多一筆。該管理員不能使用 Email 忘記密碼；授權維護者可在已連線 VPN／SSH tunnel 的互動式終端執行 `scripts/reset_email_less_admin_password.py`，工具只接受此首管、隱藏輸入密碼、撤銷舊 Token 並留下稽核紀錄。一般註冊與一般未驗證帳號登入規則不變。
- 美食紀錄：`records` 與 `photos` 對應首頁快門、右下角畫筆、多圖順序、刪除與重新編輯。
- 留言與愛心：`platform_comments`、`record_likes` 對應貼文留言數、留言內容與愛心數。
- 標註：`record_mentions` 對應快門／畫筆的好友標註；地點 ID 寫入 `records.restaurant_id`，照片 EXIF GPS 的顯示標籤寫入 `records.location_text`。
- 好友與聊天：`friend_requests`、`chat_messages` 對應好友搜尋、邀請、批准、好友列表與私有聊天室。
- 會員：`memberships`、`payment_transactions` 目前是 Demo 付款，不會連接真實金流。
- 推薦：餐廳原始資料、`price_range` 價位帶與兩類圖片 URL 已存在；價位帶有五個新台幣區間，缺值保留 NULL。推薦卡片／詳情優先使用餐廳圖；缺漏或載入失敗時用食物圖，失敗時顯示本機佔位圖。圖片由外部 HTTPS 主機提供，不是上傳至 Foodiemo；授權與原站連結可用性需由維護者確認。正式庫目前有 1 次推薦執行、3 個結果與 3 筆互動事件；價位帶尚未納入推薦排序。
- 餐廳標籤：`tags_rows` 和 `restaurant_tags_rows` 已匯入，提供六類篩選標籤及餐廳對照；搜尋 API 與前端篩選器尚未接上。26 家尚無標籤的餐廳仍保留在 `restaurant_rows`。
- 管理員功能（正式 schema 已套用 0008）：管理 API 以伺服器端 admin role 限制；帳號狀態、貼文／留言審核、檢舉處理都會寫入 `admin_audit_logs`。檢舉原因寫入 `content_reports`。首位管理員已由互動式 `scripts/promote_first_admin.py` 建立；密碼只保存 scrypt 雜湊，不綁定 Email。離線重設工具也只寫入新密碼雜湊並記錄 `admin.password_reset.offline`，不會記錄新密碼或 Email。
- 推薦評估：登入者每次看到的推薦執行寫入既有 `recommendation_runs`／`recommendation_items`；版本、請求情境、排序、分數／理由可於管理頁檢視。詳情與地圖點擊寫入 `user_restaurant_events`，綁定該使用者自己的推薦執行，管理頁提供各推薦項目互動數。

## 權限與資料安全現況

- 本次盤點連線回報 `transaction_read_only=on`。Migration `0011_restaurant_image_links` 在備份 checksum、schema、27 表筆數與隔離還原核驗後，先於隔離還原成功套用及核對，再由 guarded 腳本以單一 transaction 套用正式庫。唯讀確認 0011、27 張表、158 間餐廳、31 筆餐廳圖、158 筆食物圖與 0 筆雙欄皆空。備份位於 `backups/20261006_162047`。
- API 以登入 Session 判斷使用者。Email 僅在自己的 `/api/me` 與驗證／密碼重設流程使用；好友搜尋、好友列表、聊天室對象與貼文回應不提供其他使用者的 Email。照片檔案由作者限定讀取，好友關係不會自動開放私人照片。
- 圖片上傳會重新實體化為 JPEG，原始 EXIF 不會直接保存；照片 GPS 只保存為前端顯示用的短地點文字。
- 本文件與 Git 提交不放入 `.env`、SMTP 密碼、資料庫密碼、Session Token 或照片檔案。

## 持續更新流程

1. 修改 migration 或資料庫綁定前，先建立新的本機備份並記錄目錄。
2. 套用後執行 `scripts/inspect_db.py` 或同等唯讀盤點，更新本文件的版本、表格與筆數。
3. 在「更新紀錄」新增日期、migration／API 變更、備份位置與測試結果。
4. 執行來源保護、單元、瀏覽器與需要的 PostgreSQL 整合測試。
5. 將本文件與程式變更一起提交並推送到 GitHub。
